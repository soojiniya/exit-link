# fair_retry_v1 본 실험 사전 설계 (Pre-registration)

- 상태: **본 실험 실행 전 고정.** 이 문서의 SHA-256은 모든 `plan.json`의 `source_sha256`에 기록됩니다. 본 실험 계획을 만든 뒤 이 문서를 고치면 그 계획은 `validate()`에서 거부됩니다. 변경이 필요하면 새 계획을 만들고 변경 이유를 기록합니다.
- 프로토콜: `fair_retry_v1` / 연구 브랜치: `research/fair-fixed-retry`
- 목적: 재시도 횟수·시간 예산을 같게 맞춘 상태에서 **자동 경로 우회의 추가 효과**를 검증한다.

## 1. 비교 대상과 평가 지표

| 구분 | 내용 |
|---|---|
| 비교 방식 | `fixed_retry`(Fixed + Retry) vs `exit_link`(EXIT-LINK) |
| 1차 지표 | **delivered**: 메시지 송신 후 9초 관측 창 안에 목적지 N4의 수신 로그가 관측됨. 실패 메시지도 분모에 포함 |
| 1차 비교 | **EXIT-LINK − Fixed + Retry**, 전체 유효 블록에 대한 전달 성공률 차이(%p) |
| 2차 지표 | 6초 안 ACK 비율(`ack_6s`), 조건별 차이, 메시지당 시도 횟수(N1 로그), ACK 지연(조건부), Heartbeat 제어 트래픽 |
| 보고하지 않음 | 메시지 단위 Wilson 신뢰구간(같은 셀의 메시지 3개는 독립이 아님) |

## 2. 장애 조건 8가지

| 조건 | 타이밍 | 내용 |
|---|---|---|
| normal | none | 장애 없음 |
| single_failure | before_send / inflight | N2 정지 |
| sequential_failures | before_send / inflight | N2 정지, +1초에 N3 정지 |
| restart | before_send / inflight | N2 정지, +1초에 N2 재시작 |
| no_route | before_send | N2·N3 정지(N1→N4 경로 없음) |

메시지: 셀당 3개, 송신 시각 +0.05 / +0.8 / +2.5초(inflight는 0 / +0.8 / +2.5초). 장애 주입·재시작·전송 시각은 기존 `aligned_v3.trial()`을 수정 없이 사용하며 허용 오차는 100ms입니다.

## 3. 재시도·타임아웃 예산 (두 방식 동일)

| 항목 | 값 |
|---|---|
| 재시도 횟수 | `max_retries=3` = 최초 전송 **제외** 재시도 3회 → 최대 4회 시도 |
| 재시도 위치 | 출발 노드 N1 |
| 재시도 간격 | 0초(직전 시도 실패 직후) |
| 재시도 대상 오류 | `connection_failed`, `timeout`, `invalid_response` |
| 홉 타임아웃 | 1.5초 |
| 클라이언트 마감 | 6초 |
| 관측 창 | 9초 |
| TTL | 16, 시도마다 경로 홉 수만큼 예약 |
| 경로 정책 | Fixed + Retry: 항상 N1→N2→N4 / EXIT-LINK: Heartbeat 링크 상태 + 실패 링크 제외 |
| Heartbeat | Fixed + Retry 꺼짐 / EXIT-LINK 켜짐(0.1초 probe, 2회 실패 시 down) |

알려진 차이(경로 정책 외): EXIT-LINK만 Heartbeat를 실행하므로 제어 트래픽과 계측 로그 비용이 생기고, 경로가 없으면 `no_route`로 일찍 끝날 수 있습니다. Windows에서 실패 시도 1회가 약 1.5초 걸리므로 Fixed + Retry의 4번째 시도는 6초 클라이언트 마감 직후에 끝날 수 있습니다. 이때 시도 횟수는 클라이언트 응답이 아니라 N1 로그로 집계합니다.

## 4. 통계 방법

- **독립 단위:** 블록 = (조건, 타이밍, 반복 번호). 한 블록에는 두 방식의 셀이 하나씩 있으며, 셀별 값은 메시지 3개 중 성공 비율(0, 1/3, 2/3, 1)입니다.
- **1차 비교 신뢰구간:** 층화 블록 bootstrap. 8개 조건 각각의 안에서 블록을 복원 추출하고, 전체 평균 차이를 계산합니다. 10,000회, seed `20261117`, 백분위 2.5–97.5%.
- **1차 검정:** 블록별 차이의 부호에 대한 정확 이항 부호 검정(양측), 동률 제외. **단일 1차 검정이므로 보정하지 않습니다.**
- **2차(조건별) 검정:** 8개 조건별 부호 검정에 Holm 보정을 적용합니다. 조건별 신뢰구간은 그 조건 안의 블록 bootstrap입니다.
- **해석 규칙:** 구간 폭이 0이면 "표본 안에서 변이가 없음"으로 적고 불확실성이 없다는 뜻으로 쓰지 않습니다. 유의하지 않은 결과도 그대로 보고합니다.

## 5. 셀 판정 기준

| 상태 | 정의 | 처리 |
|---|---|---|
| 유효 셀 | 체크포인트됨, `comparable=true` | 분석에 포함 |
| 무효 셀 | 체크포인트됨, `comparable=false`(시각 위반·정리 실패 등) | 대응 블록의 **두 셀 모두** 제외, 사유 기록 |
| 중단 셀 | 폴더는 있으나 체크포인트 없음 | 감사 후 명시적으로 제외. 블록의 두 셀 모두 제외 |
| 미실행 셀 | 폴더 없음 | 분석에서 제외(`not_checkpointed`) |

성공·실패는 자동으로 판정하지 않습니다. 중단 셀은 "성공" 또는 "실패"가 아니라 "분석 제외"입니다. 완료된 셀은 재실행하거나 덮어쓰지 않습니다.

## 7. 실험 중단과 재개 절차

원칙: 원본 셀 파일·`plan.json`·실행 잠금(`.benchmark.lock`)·lease 파일을 **삭제·수정·이동하지 않습니다.** 감사 기록은 별도의 추가 전용 파일 `RUN/audit/exclusions.jsonl`(해시 체인)에만 씁니다.

1. 중단되면 아무것도 지우지 않고 시각·마지막 셀 번호를 기록합니다.
2. 남은 노드 프로세스를 종료합니다. 노드 포트가 비어 있지 않으면 감사 명령이 거부됩니다.
3. `--check RUN`이 체크포인트 없는 폴더를 알려 줍니다.
4. 중단 셀 감사: `--audit-interrupted RUN --cell N --reason "<사유>" --auditor "<이름>"`
   - 셀 폴더의 파일 목록·크기·SHA-256, journal 상태, lease 내용과 해시, 포트 상태, 짝 셀 상태를 기록합니다.
   - 짝 셀이 아직 실행되지 않았다면 `excluded_partner`로 함께 제외되어 실행되지 않습니다. 짝 셀이 이미 완료됐다면 파일은 보존되고 분석에서만 블록이 제외됩니다.
5. 셀 폴더 없이 lease만 `needs_audit`인 경우: `--acknowledge-lease RUN --reason ... --auditor ...`
6. 재개: 같은 `--execute RUN --max-cells N`. 감사 기록이 지금의 lease 파일 해시를 인정한 경우에만 실행되며, 감사된 셀과 제외된 짝 셀은 건너뜁니다. 감사 이후 중단 셀 폴더의 파일이 하나라도 바뀌면 실행이 거부됩니다.
7. 분석에서는 감사 제외 블록이 `exclusions.csv`에 사유와 함께 남습니다.

## 8. 파일럿과 본 실험 데이터 분리

| 구분 | 파일럿 | 본 실험 |
|---|---|---|
| 실행 폴더 | `data/measured/fair-retry/pilot-*` (기존 `pilot-e02bb314`) | `data/measured/fair-retry/main-*` |
| 시드 | 20261116 | 20261117 |
| 분석 결과 | `outputs/fair-retry-pilot-*` | `outputs/fair-retry-main-*` |
| 용도 | 절차 점검 전용, 최종 주장에 사용하지 않음 | 1차 주장 |

분석 스크립트는 실행 폴더 하나만 받으며 여러 실행을 합치지 않습니다. 파일럿 요약에는 "절차 점검 전용" 문구가 자동으로 들어갑니다. 기존 v3 데이터(`data/measured/v3-*`)와 파일럿 원본은 읽기 전용입니다.

## 9. 파일럿 이후 변경 사항 (탐색적 분석과 구분)

파일럿 결과를 본 뒤 다음을 바꿨습니다. 1차 지표·1차 비교·조건·예산은 바꾸지 않았습니다.

1. 시도 횟수를 N1 로그의 `delivery_result`에서 집계(클라이언트 마감으로 누락되던 값).
2. 비층화 bootstrap → 층화 블록 bootstrap(10,000회), 메시지 단위 Wilson 구간 제거.
3. 중단 셀 감사·제외·재개 절차 추가, 파일럿·본 실험 단계와 본 실험 시드 고정.
